An extension is a signed WASM module plus a manifest. It adds behavior through
declared capabilities and host calls. It does not receive direct access to
Spacedrive databases or arbitrary host resources.

## Extension definition

The extension macro declares stable identity and exported features:

~~~rust
use spacedrive_sdk::prelude::*;

#[extension(
    id = "com.example.media",
    name = "Media Tools",
    version = "1.0.0",
    jobs = [build_proxy],
)]
struct MediaTools;
~~~

Package identity, version, minimum host compatibility, signature, and
capabilities are visible before installation.

## Capabilities

Capabilities name what the extension may request:

- source and subtree reads;
- writes to a selected source scope;
- extension model access;
- sidecar creation;
- named network destinations;
- registered jobs and actions;
- interface contributions.

The user grants or denies them. Runtime checks apply on every host call.

## Models

Typed models store facts the extension owns. A model chooses a scope:

- **record** for one observed source object;
- **content** for confirmed identical bytes;
- **standalone** for an object with its own identity.

Models that cannot be reconstructed belong to the assertion layer and survive
source reindexing. Generated facts record their generator and input generation.

## Jobs

Jobs perform long or interruptible work. Their serializable state supports
checkpoints when the algorithm can resume safely.

~~~rust
#[derive(Serialize, Deserialize, Default)]
pub struct ProxyState {
    pub completed: Vec<Uuid>,
}

#[job(name = "build-proxy")]
fn build_proxy(ctx: &JobContext, state: &mut ProxyState) -> Result<()> {
    // Read through granted byte providers, commit output, then checkpoint.
    Ok(())
}
~~~

The host owns scheduling, progress, logs, deduplication, cancellation, and
recovery classification.

## Actions

Actions are user-invoked operations. They return typed output and can dispatch a
job.

Risky actions separate preview from commit. The preview identifies exact
records, destinations, permissions, conflicts, and protection consequences.
Commit executes the accepted plan rather than recomputing hidden intent.

## File kinds

A file-kind registration can use:

- filename extension;
- MIME or platform type;
- magic bytes;
- provider metadata;
- structural probing.

The result names capabilities such as preview, metadata extraction, streaming,
editing, or export. Installed operating-system handlers can contribute evidence
without becoming trusted executors.

## Previews and sidecars

A preview declares the source kinds it accepts, range-read needs, output
variants, and fallback behavior. It can render directly or request a
deterministic sidecar.

Persistent proxies and thumbstrips follow source policy. Rebuildable thumbnails
can remain cache data while their input and generator are available.

## Views

Extensions contribute named views, inspector sections, and context-menu
commands through a declarative UI manifest. Views query registered models and
records. They do not ship an unrestricted frontend application inside the
filesystem interface.

## No built-in agent runtime

Spacedrive extensions add deterministic tools and data capabilities. An
external agent can call those registered operations through the same CLI or MCP
surface as a person.

The extension system does not provide a parallel autonomous agent, memory, or
shell runtime.

## Absence and removal

Source records and durable models remain understandable when an extension is
disabled. The interface reports the missing handler and offers safe fallback
behavior.

Uninstalling code does not silently delete original files, assertions, or
persistent sidecars.
